# 0.1.6 修复与验收记录

2026-10-29 形成的本地验收记录。正式发布状态以 GitHub Releases 为准。

## 本次修复

- 原子保存不再先删除目标文件。临时文件写入、同步或最终替换失败时，报告失败并保留原文；支持随后重试。
- 同一窗口的保存、快照写入和快照清理串行执行，清理/保存使旧的排队任务失效。关闭会等待清理完成，防止旧快照在保存或关闭后重新出现。
- 另存为由主进程清理旧、新路径的快照，不再通过已失效的旧路径清理请求。
- 编辑快照按最长约 1.8 秒的输入周期触发，连续输入不会重置等待时间；撤销回已保存内容时取消定时器并清理快照。
- 保存期间产生的新编辑保持未保存状态，并继续生成快照；关闭时不会将这类新编辑当作已经保存。
- 自动测试图片改为可见的 480 × 240 PNG，按名称验证全部九种引用/排版图片。补齐 HTML block 后的空行，确保引用式图片真正渲染，并检查并排、48% 宽度、居中和右浮动的实际位置。
- 大文档基准改为运行真实应用，测试原生文本输入、真实预览、全文刷新，并等待字体与本地图片。公式样本准确包含 1000 个公式。

## 已通过的验证

```text
npm test
npm run test:desktop
npm run benchmark:large
git diff --check
```

桌面回归包含：sandbox、菜单/键盘历史、输入框历史隔离、全部本地图片路径、危险属性、链接策略、宽度迁移、主题、窗口尺寸和分栏、HTML/PDF 导出、多窗口隔离、预置快照恢复，以及下列新增场景：

- 连续输入时实际生成快照；撤销回磁盘内容后清理。
- 真实另存为菜单清理旧路径和新路径。
- 延迟文件替换时继续输入，保存完成后仍保持未保存状态。
- 延迟快照提交时保存或撤销，旧快照不会残留。
- 关闭时取消、不保存、保存三条路径。
- 通过真实编辑生成快照，进程直接退出后再次启动，提示恢复并保存。

另用真实应用打开人工验收样例，确认六张图片和公式成功渲染，并检查浅色、深色截图。

## 性能记录

本机单次测量，单位毫秒。输入响应指原生 insertText 到编辑器状态更新；输入到预览包含应用自己的调度等待。完整结果见 `reports/benchmark-latest.json`，包含 IPC 和轮询开销，不作为稳定阈值。

| 样本 | 首次打开并完成布局 | 输入响应 | 输入到预览 | 全文刷新 |
| --- | ---: | ---: | ---: | ---: |
| 5000 行 Markdown | 1032.08 | 17.85 | 145.34 | 199.92 |
| 1000 个公式 | 1095.14 | 14.12 | 156.83 | 209.64 |
| 800 行表格 | 930.90 | 13.82 | 1166.84 | 170.18 |
| 300 张本地图片与 HTML | 533.78 | 11.39 | 1051.40 | 44.65 |

现有构建的大 chunk 提示、Node shell 调用弃用提示和 Windows 网络监听日志仍会出现，不影响上述回归结果。长表格和 HTML/图片文档的预览更新会等待约一秒的全文刷新调度。
